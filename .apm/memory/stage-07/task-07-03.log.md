# Task 7.3 - Browser Workflow E2E Coverage

## Summary
Added runnable Playwright browser workflow coverage for the authenticated Chinese operator workbench. The suite uses deterministic mocked `/api/*` responses, covers the requested high-value flows, and avoids live external source collection or service orchestration.

## Details
Reviewed the dependency context across source operations, endpoint helpers, backend source/alert/manual-entry/export routes, and QA documentation before choosing the test architecture. A full Compose browser E2E path would require heavier PostgreSQL, Redis, backend, worker, and reverse-proxy orchestration, so the implemented default is a deterministic frontend browser suite that runs the local Next.js app and intercepts API calls in the browser.

The test setup adds Playwright as a minimal frontend dev dependency, a local Chromium project config, and one workflow spec with stateful API mocks. The mocks require the bearer token after login, return stable intelligence/source/alert/manual-entry/export data, and fail unmocked API routes so endpoint drift is visible.

The suite covers:

- Login-gated workbench access and authenticated API calls.
- Intelligence list, detail navigation, source attribution, and CSV download initiation.
- Manual-entry client validation failure and successful submission.
- Source operations status display, processing pipeline trigger, and separate backend alert evaluation trigger.
- Alert detail review, linked intelligence access, and alert status update.

Documentation was updated so `docs/testing.md`, `docs/qa/frontend-page-checklist.md`, and `docs/qa/coverage-pass-summary.md` reference `cd frontend && npm run e2e`, one-time Chromium installation, mocked-API scope, and remaining live-stack gaps.

## Issues
None blocking. The first browser run failed because Chromium had not yet been installed; installing Chromium resolved that. A subsequent run exposed localhost proxy interference during Playwright's readiness probe, and `frontend/playwright.config.js` now sets localhost `NO_PROXY` values so local E2E runs do not route through the external proxy.

## Important Findings
Local proxy environment variables can cause Playwright's web-server readiness probe for `127.0.0.1:3000` to receive a false HTTP 400 before Next.js starts. The new Playwright config explicitly appends `127.0.0.1,localhost` to `NO_PROXY`/`no_proxy` and also sets those values on the web-server command.

The new browser workflow suite validates UI behavior and frontend endpoint wiring with mocked API responses. It does not replace live Compose validation for reverse-proxy, backend, PostgreSQL, Redis, worker, scheduler, or live source integration.
