# Task 10.2 - 访客只读前端

## Summary

在分支 `feat/guest-readonly-frontend`（提交 `d1e6c53`）实现访客只读前端：态势总览、威胁情报（列表/详情）、数据源三个公开页未登录可访问，告警/手工录入/用户管理保持登录可见；访客态隐藏全部写操作并展示「访客模式」提示与登录入口。`pnpm build`、`lint`（biome 零警告 + tsc 零错误）、`test` 17/17 全绿；浏览器真实后端双态走查通过。

## Details

1. **公开路径工具**：新增 `src/utils/access.ts` 的 `isPublicPath()`，前缀匹配 `/dashboard`、`/intelligence`、`/sources`（含详情 `/intelligence/:id`）。
2. **守卫改造**（`src/app.tsx` getInitialState + onPageChange）：
   - 公开页：无 token 直接以访客进入；有 token 尝试恢复会话（失效静默降级为访客，不强制跳登录）。
   - 受保护页：无 token 或会话失效 → 跳登录并携带 redirect。
3. **访问控制**（`src/access.ts`）：新增 `canOperate`（登录可见），`/alerts`、`/manual-entries` 路由加 `access: 'canOperate'`；`/users` 保持 `canAdmin`。菜单与路由守卫双重控制。
4. **访客视图**：
   - `UserAvatar` 访客态渲染「访客模式」Tag + 「登录」按钮（携带当前页 redirect），登录后回跳原页。
   - 情报列表页：导出 CSV 与手工录入快捷入口仅登录显示（手工录入保持 is_admin 语义）。
   - 情报详情页：导出 Markdown/PDF 按钮仅登录显示。
   - 数据源页：操作列（任务日志/启停）与「手动触发同步」按钮仅登录显示。
5. **401 兼容**：匿名只读请求（无 Authorization）后端返回 200，不触发跳登录；写端点 401 仍走既有「清凭证跳登录」流程（`requestErrorConfig.ts` 未改动）。
6. **路由修复**：归位后 `/intelligence` 嵌套路由（父无 name + 父子同 path）在 ProLayout 菜单折叠丢失「威胁情报」项；扁平化为顶层路由 + 独立隐藏详情路由，菜单恢复（登录 6 项 / 访客 3 项）。
7. **聚焦测试**（新增 7 例，总计 17 例）：`isPublicPath` 边界（精确/子路径/受保护/相似前缀不误判）；UserAvatar 访客态（提示+登录按钮、点击跳转 redirect）、登录态（用户名、无访客提示）。另修 e2e 一处 `hasOwnProperty` lint 警告（`in` 操作符）。

## Important Findings

- **归位后路由菜单缺失**：`/intelligence` 的嵌套路由（父无 name + 父子同 path）在 ProLayout 菜单生成中折叠，导致「威胁情报」菜单项缺失（9.4 走查时该结构正常，9.5 归位后出现；可能与环境/依赖版本差异有关，未深挖）。扁平化为顶层路由后稳定。9.5 的 E2E 未覆盖到该缺陷。
- **登录按钮点击时序**：走查中 Playwright 对登录页「登 录」按钮 click 偶发超时（按钮可见且 count=1），用 `form.requestSubmit()` 绕过；非本任务引入（9.1 即有该登录页），记录备查。
- 走查期间 postgres 容器 IP 曾变化（172.18.0.3 → 172.18.0.4），本机联调命令需动态获取容器 IP。
- **收尾清理教训**：`pkill` 只杀掉了 cross-env 包装进程，utoopack-dev-server 子进程成为孤儿继续服务（proxy 指向已被杀的后端 8002），用户随后看到页面挂骨架屏（/api 全 504）。后续收尾应整体确认进程树退出，或明确保留联调环境并告知；页面级验证必须以截图/视觉确认为准，DOM 快照与接口探测不足以排除环境类故障。
