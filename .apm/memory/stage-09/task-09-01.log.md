# Task 9.1 - Pro v6 前端底座搭建

## Summary

在 `frontend-pro/` 用官方 Ant Design Pro v6.0.3 模板搭建了可构建、可登录、带中文安全运营布局壳的应用底座。登录流转、路由守卫、401 统一处理均经浏览器端到端验证（mock 模式，契约与真实后端一致）。全部验收项通过，已提交至 `feat/frontend-pro-scaffold` 分支。

## Details

1. **脚手架与裁剪**：`pnpm create umi` 需交互 TTY 无法使用，改用等价方式 clone 官方 ant-design-pro 仓库（v6.0.3，React 19 + Umi Max 4.7 + antd 6 + antd-style + Biome，构建器 utoopack）。先运行官方 `scripts/simple.js` 精简，再手动删除 chatbot（AI 对话）、table-list、list、Admin、Welcome 等残留页面、模板测试与 husky/commitlint/CI 配置；语言包仅保留 zh-CN，未使用官方 `i18n-remove`（保留 i18n 框架能力）。
2. **API 契约层**：`backend/.venv` 整体缺失（非仅缺 fastapi），openAPI 自动生成不可行，按 Task Prompt 预案手写 TypeScript 契约层 `src/services/<domain>/`（auth/users/alerts/intelligence/sources/manualEntries/exports/health + shared），typings 与请求函数逐字段对齐 `backend/app/api/schemas/` 与路由 query 参数（经核对修正了 intelligence 列表参数、alerts risk_level、users 无分页等偏差），目录结构对齐 openAPI 插件产物，`config/config.ts` 中保留了注释化的 openAPI 配置便于将来切换。
3. **布局壳**：ProLayout 侧边导航、亮色、固定头部，克制配色（antd 默认主蓝 + 系统字体栈），六项中文导航：态势总览、威胁情报、告警、数据源、手工录入、用户管理（用户管理 `access: canAdmin`，基于 `is_admin`）。删除了模板的 GA 统计、SettingDrawer、营销背景图（外链 CDN）、社交登录图标、语言切换 UI。
4. **认证对接**：登录页（邮箱+密码）对接 `POST /auth/login`；token 存 localStorage（key `sentineldrive.access_token`，沿用旧前端约定）；umi request 拦截器附加 `Authorization: Bearer`；401 统一处理（清凭证 + 派发 session-expired 事件 + 带 redirect 跳登录）；`getInitialState` 恢复会话（GET /auth/me）+ `onPageChange` 路由守卫。base path 为 `/api`（生产经 Caddy `handle_path`，开发经 `config/proxy.ts` 代理到 `localhost:8000`，可用 `BACKEND_PROXY_TARGET` 覆盖）。
5. **路由占位**：六个页面为共享 `PlaceholderPage` 组件的空态占位（中文标题 + 职责说明 + 「Task 9.3/9.4 实现」标注），无任何虚构数据。
6. **mock**：`mock/auth.ts` 完整模拟 `/api/auth/login|me|logout` 真实契约（含 401 错误结构 `detail.error.{code,message}`），演示账号 `admin@sentineldrive.local / SentinelDemo2026`（仅 mock，注释标明）。
7. **验证方式**：pnpm build/tsc/biome/test 全绿；`pnpm start`（mock 模式）+ 浏览器实测：未登录访问 `/alerts` → 跳登录页带 `redirect=%2Falerts`；登录成功回跳；退出登录回登录页；整页中文无 demo 残留（截图确认）。

## Compatibility Concerns

- `frontend-pro/tsconfig.json` 将模板的 `declaration: true` 改为 `false`：TS 7 在 noEmit 检查下对 `config/config.ts` 的 `export default defineConfig(...)` 报 TS2883 可移植性错误；noEmit 场景 declaration 无实际作用，但后续任务若在此工程开启声明输出需重新评估。
- 9.5 部署切换注意：`docker-compose.yml` 中旧 frontend 服务仍指向 `frontend/`（本任务按约定未改动）；切换时新前端的构建产物 base path 为 `/`，请求经 `/api` 由 Caddy 转发，与现有反代语义一致。
- `max build` 内部会执行 `pnpm install` 做依赖校验：pnpm 11 需先 `pnpm approve-builds --all` 批准 esbuild/core-js 等构建脚本（已批准并记录在 `pnpm-workspace.yaml`），否则构建以 exit 1 失败。

## Important Findings

- **菜单语言方案**：umi 的 locale key 菜单翻译（routes `name: 'menu.xxx'`）在 utoopack 构建链下运行时不生效（翻译值与路由数据均已打包，但 IntlProvider 链路未消费，未深查打包器内部）。改用官方 simple.js 裁剪脚本的同款做法——路由 name 直接写中文，i18n 框架能力（locale 插件、zh-CN 包、antd locale）保留。9.3/9.4 页面若需 intl，建议页面文案直接中文或先验证 formatMessage 链路。
- **后端 venv 缺失**：`backend/.venv` 不存在（此前认知为「缺 fastapi、安装失败」，实际整个虚拟环境缺失），本机起真实后端需先重建环境；这是 9.3 真实联调的前置条件。
- **模板 dev 脚本语义**：`pnpm dev` = `MOCK=none`（走 proxy 连真实后端），`pnpm start` = mock 模式。9.3 联调用 `dev`，纯前端开发用 `start`。
