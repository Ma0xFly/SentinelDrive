## Details
Reviewed the current README, deployment/environment docs, Compose file, Makefile targets, backend scripts, worker scripts, Caddy routing, backend health routes, source API routes, and Celery task entry points before editing. Kept the task documentation-only except for `.gitignore`, where `backups/` was added so host-side dump files produced by the documented commands are not accidentally staged.

The backup procedure writes timestamped custom-format PostgreSQL dumps under `backups/postgres/` using `docker compose exec -T postgres` and container-side `POSTGRES_USER`/`POSTGRES_DB` variables. The restore procedure clearly warns that restore replaces the current database, stops application writers, keeps PostgreSQL/Redis available, uses `dropdb --force` plus `createdb`, restores with `pg_restore`, reruns migrations, and restarts services.

The troubleshooting section records known runtime issues from Compose verification: WSL Docker startup, local Caddy HTTPS versus `CADDY_HOST=:80`, worker egress/DNS failures, NVD 120-day window and optional API key behavior, Passlib/bcrypt warning avoidance, PostgreSQL enum cast errors, and placeholder secret validation.
