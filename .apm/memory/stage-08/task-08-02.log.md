# Task 8.2 - 外部/AI 情报 Ingest API

## Summary

已实现认证保护的 `POST /intelligence/ingest`，用于接收外部/AI collector 整理后的情报，并写入现有 raw intelligence、normalized intelligence 和 source attribution 流程。端点支持 CVE 优先去重、无 CVE 时按外部 ID/source attribution 等稳定信号去重，重复提交会返回并更新现有核心记录，不创建重复核心情报。

## Details

- 新增 `IntelligenceIngestRequest` 和 `IntelligenceIngestResponse` schema，支持 `source_name`、`source_url`、`platform`、`title`、`summary`、`description`、`external_id`、`cve_id`、`cnvd_id`、`vendor_advisory_id`、`affected_products`、`components`、`attack_surfaces`、`severity`、`external_score`、`published_at`、`collected_at`、`dedup_key`、`content_hash`、`raw_payload` 和 `tags`。
- 新增 `backend/app/services/intelligence_ingest.py`，集中处理 URL 规范化、内容哈希、幂等去重、轻量 raw payload 脱敏保存、normalized intelligence 创建/合并和 source attribution upsert。
- `POST /intelligence/ingest` 要求 bearer 认证；未认证请求返回 401，字段缺失或格式错误返回现有 FastAPI 校验错误风格。
- 敏感字段处理遵循现有 `safe_metadata`、`safe_text`、`safe_url` 规则：明显凭证文本会被拒绝，raw payload 中的 `authorization`、`token` 等敏感 key 会被移除，URL 中敏感 query 参数不会进入响应/保存后的 source URL。
- 审计事件使用现有 `AuditAction.MANUAL_ENTRY`，metadata 只记录 ingest 来源、去重结果、dedup key 和安全来源信息，不记录 raw payload。
- 未引入 AI 分析、知识图谱、工单、外部通知、调度器或自定义评分规则。
- 未使用 subagent。
