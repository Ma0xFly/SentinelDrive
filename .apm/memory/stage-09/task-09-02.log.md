# Task 9.2 - 威胁统计聚合 API

## Summary

新增认证保护的 `GET /stats/overview` 聚合端点，单次请求返回仪表盘所需的五块统计数据（总量、四个维度分布、30 天趋势、告警、来源 Top 10），配套 6 个聚焦测试全部通过，既有后端测试无回归。

## Details

- 新增 `backend/app/api/schemas/stats.py`：`StatsOverviewResponse` 及子模型（totals / 趋势点 / alerts / sources），分布字段为 `dict[str, int]`，趋势点为 `{date, count}`。
- 新增 `backend/app/api/routes/stats.py`：`prefix="/stats"`，暴露 `GET /overview`，复用 `get_current_user` 认证依赖（未认证 401，与既有列表 API 一致）。
- 响应结构：`totals`（总数 / 近 24h / 近 7d 新增，按 `first_seen_at`）；`by_intelligence_type` / `by_severity` / `by_risk_level` / `by_processing_status`（按枚举全量补零，条目数由枚举上界约束）；`trend`（近 30 天按天新增情报，缺失日期补零，固定 30 条）；`alerts`（总数 / 按状态分布 / 近 30 天趋势，按 `triggered_at`）；`sources`（启用数据源数 / 按关联去重情报数排序的 Top 10）。
- 遵循代码库既有双路径约定：真实 SQLAlchemy Session 走 SQL 聚合（GROUP BY + `date(timezone('UTC', col))` 确定性 UTC 按天截断，来源 Top N 用 `count(distinct(threat_intelligence_id))` JOIN）；非 Session 测试假 session 走 Python 内存聚合，两者口径一致。
- 时间窗为模块常量：`TREND_DAYS = 30`、24h / 7d `timedelta` 常量、`SOURCE_TOP_LIMIT = 10`，未引入新配置项，无新表、无迁移。
- 口径决策：所有计数不按 status 过滤（与情报/告警列表 API 默认行为一致）；分布键用枚举全量补零，保证响应结构稳定；来源 Top 10 不限状态（含已禁用但有关联情报的来源），平局按名称升序，只含有 ≥1 关联情报的来源；响应只含计数、日期、来源 id 与名称，无敏感字段或原始 payload。
- 测试 `backend/tests/test_stats_api.py` 按既有假 session 风格编写，覆盖：未认证 401、空库全零结构（含趋势 30 天日期序列）、多类型/严重度/风险/处理状态分布计数与 24h/7d 窗口、趋势补零与窗口边界（首日 00:00 含入、前一日微秒级排除）、告警状态分布与趋势窗口（40 天前告警不计入趋势但计入总数）、来源 Top N 去重计数/平局排序/禁用来源/零关联来源/无归属链接忽略。

## Important Findings

- `backend/tests/test_migrations.py` 的 6 个测试存在既有缺陷：用相对路径 `Path("migrations/versions/...")` 读文件，**从仓库根目录运行必失败、从 `backend/` 目录运行才通过**（已在未含本任务改动的原始工作区复现确认）。建议后续 Task 将测试命令统一为「在 `backend/` 目录运行 pytest」，或修复为基于 `__file__` 的路径。
- `httpx` 是测试直接依赖但未列入 `backend/requirements.txt`（fastapi 0.111.0 也不会带入它），新环境搭建时会缺装；建议补入测试依赖说明。
- 仪表盘消费方（并行前端任务）需注意：分布键为枚举值全量补零、趋势固定 30 条（最旧→最新）、来源 Top 10 含已禁用来源。
