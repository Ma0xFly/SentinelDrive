# Task 1.3 - Frontend Application Shell

## Summary
Implemented the Chinese Next.js operations workbench shell with MVP placeholder routes, shared layout primitives, responsive styling, and a public API client placeholder. Committed the work on `feat/frontend-workbench-shell` at `9c3bb36`.

## Details
Inspected the platform scaffold contracts before editing: Compose keeps `frontend` on port `3000`, public `NEXT_PUBLIC_API_BASE_URL` remains `/api`, and Caddy routes `/api/*` to the backend. Built the shell inside `frontend/` only, using Chinese labels and restrained security-operations styling rather than a marketing page.

Added reusable shell components for sidebar navigation, page sections, metric strips, toolbars, and empty states. Added placeholders for intelligence list, intelligence detail, alerts, source management, manual entry, and user basics. Added `frontend/lib/apiClient.js` to read `NEXT_PUBLIC_API_BASE_URL` without hardcoded secrets.

During validation, the initial scaffold dependency set was not installable with npm because `next@15.0.0` did not accept stable `react@19.0.0`. Updated the frontend package to `next@15.5.18`, `react@18.2.0`, and `react-dom@18.2.0`; added a lockfile. npm audit then reported vulnerable transitive PostCSS through Next, so added a scoped `postcss@8.5.10` override and revalidated.
