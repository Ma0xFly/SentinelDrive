# Task 3.4 - Manual Entry API

## Summary
Implemented authenticated manual-entry APIs that create, list, view, update, deduplicate, and audit analyst-submitted intelligence using the existing raw and normalized intelligence tables. Changes were committed on `feat/manual-entry-api` as `71c37e8 feat: add manual entry api`.

## Details
- Added request/response schemas for manual entry create/update/detail responses, including validation for categories, required attribution, CVE format, enum-backed vehicle component and attack surface values, status, tags, and obvious unredacted credential assignments.
- Added `POST /manual-entries`, `GET /manual-entries`, `GET /manual-entries/{entry_id}`, and `PATCH /manual-entries/{entry_id}` routes protected by the existing bearer-token auth dependency.
- Mapped manual categories to existing MVP `IntelligenceType` values. Research leads map to `advisory`, carry `research_lead` tags, and default to `under_review` status.
- Created manual submissions through the existing `RawIntelligence`, `ThreatIntelligence`, and `ThreatIntelligenceSource` models with metadata-only raw retention and source attribution.
- Implemented deterministic dedup keys: CVE-backed entries use `manual:cve:<CVE>`, non-CVE entries hash category/title/source attribution. Duplicate manual submissions return the existing record with HTTP 200 and write an audit event instead of creating duplicate normalized intelligence.
- Added audit events for create, duplicate submission, update, and status change actions.
- Updated backend docs to describe manual-entry endpoints and current persistence/dedup behavior.
