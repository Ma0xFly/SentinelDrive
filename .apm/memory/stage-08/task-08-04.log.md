# Task 8.4 - 浏览器验证与接入文档

## Summary

为外部/AI 情报接入补上了浏览器级验证与操作者/开发者接入文档：Playwright E2E 新增外部 ingest 记录在情报列表与详情页的渲染场景（6/6 通过），新增 `docs/external-ingest.md` 并同步更新 README、testing、connectors 文档。所有自主验证通过，结果 Success。

## Details

1. 上下文整合：读取了 ingest 后端三件套（`intelligence.py` 路由/schema/`intelligence_ingest.py` 服务）、worker `ExternalIngestNormalizer`/`registry`/`dedup.external_ingest_dedup_key`、前端情报列表与详情组件、现有 E2E spec 与 testing/connectors/README 文档。确认了 ingest 请求/响应 schema（`extra="forbid"`、CVE 格式校验、中文 severity 别名、敏感文本拒绝、raw_payload ≤32KB）、201/200 双状态响应、去重优先级（cve → dedup_key → external_id → content_hash → url → text）、审计写入 `audit_events`（action `manual_entry`，不含 raw payload）。
2. E2E 场景：沿用既有 mock `/api/*` 约定，为 `GET /intelligence` 增加 `tag=external_ingest` 查询分支，避免向默认列表追加第二条记录破坏既有断言（如桌面布局测试中的单「查看」链接匹配）。新场景断言：列表的 CVE/来源/风险等级徽章/风险分、详情页的来源归属（名称+外部编号）、`external_ingest` 标签、去重键 `cve:CVE-2026-7777`、严重度与情报类型。全程不触真实后端。
3. 文档：新增 `docs/external-ingest.md`，覆盖端点与认证、字段表、校验规则、响应、去重优先级、数据落点与留存（明确 ingest 不创建 `sources` 行，不影响 `/sources` 计数）、worker 规范化/评分行为、curl 写入示例（凭证只经环境变量）、工作台与 `audit_events` 审计核验（含 `docker compose exec` psql 命令，沿用 README 备份示例的引号模式）、Playwright mock 与 live Compose 验证边界。
4. 受影响文档：`README.md` 文档索引挂新文档；`docs/testing.md` 补 `POST /intelligence/ingest` 路由、ingest 后端测试描述、E2E 覆盖清单、覆盖映射表（新增 ingest 行、更新规范化行与浏览器工作流行）；`docs/connectors.md` 在边界节补非 Connector 写入路径简述并链接新文档。
5. 版本控制：在 `docs/external-ingest-integration` 分支提交（commit `2220f53`），只含自身产出；`.apm/` 工件与无关未跟踪目录未提交。
