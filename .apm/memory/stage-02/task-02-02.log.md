# Task 2.2 - Authentication Users and Audit

## Summary
Implemented the MVP backend auth surface with signed bearer tokens, protected user endpoints, admin bootstrap audit behavior, and reusable audit event recording. Changes were committed on `feat/auth-users-audit` as `2b79fd2 feat: add authentication users and audit`.

## Details
- Added FastAPI authentication dependencies for bearer-token parsing, current-user loading, and simple admin-style authorization.
- Added auth routes for login, logout, and current-user lookup. Login records success/failure audit events, updates `last_login_at`, returns no password hashes, and uses generic credential errors.
- Added user management routes for admin-only list, create, and status update. User creation hashes passwords and user mutations write `user_change` audit events.
- Added HMAC-signed stateless access tokens using `APP_SECRET_KEY`, with an 8-hour TTL.
- Added a reusable audit helper that creates `AuditEvent` rows for auth and later domain mutations.
- Extended admin bootstrap to create/update the configured admin account, repair inactive/non-admin state, update the configured password hash when needed, and write audit events without plaintext secrets.
- Added a follow-up Alembic migration that extends the existing PostgreSQL `audit_action` enum with `login_success`, `login_failure`, and `logout`.
- Updated backend docs for auth endpoints, token assumptions, bootstrap behavior, and test coverage.
