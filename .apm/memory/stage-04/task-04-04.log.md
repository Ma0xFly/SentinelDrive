# Task 4.4 - Source Status and Job Log APIs

## Summary
Implemented authenticated backend APIs for source status, sync state, job log inspection, and source status updates on branch `feat/source-status-exports`.

## Details
Added `/sources` list/detail APIs over the existing `Source`, `SyncState`, and `JobLog` models. Responses include source id/name/type/status, enabled state, safe base URL/config, last success/failure timestamps, safe failure reason, sync state fields, consecutive failure count, and recent job counters.

Added `/sources/jobs` for paginated job log inspection with source, job status, job name, run status, retried, skipped, and sort filters. Retry and skipped state are derived from persisted job metadata written by the worker. Added `PATCH /sources/{source_id}/status` to update the existing `Source.status` value and record a `STATUS_CHANGE` audit event with before/after snapshots.

No migration was required because the existing source, sync state, job log, and audit tables already contain the needed fields.
