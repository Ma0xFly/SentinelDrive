# Task 3.1 - Raw Collection Persistence

## Summary
Implemented worker-side persistence for connector runs, covering raw intelligence records, job logs, source status, sync state, cursor updates, error isolation, and lightweight retention enforcement.

## Details
Added worker-side SQLAlchemy table definitions and a persistence service targeting the existing backend database schema without importing backend application code into the worker container. The service persists each source run independently, creates or updates source rows, ensures sync state rows exist, writes job logs, inserts or updates raw intelligence records, advances cursors only after successful runs, and records failure/skipped/retry details in metadata.

The Celery task `sentineldrive.sync_sources` now uses the persistence path when `DATABASE_URL` is configured and keeps the non-persistent runtime path available when it is not. HTML and PDF sources are forced to metadata-only retention even if a connector emits raw content.

Committed changes on branch `feat/raw-collection-persistence` with commit `ba65149` using message `feat: persist raw connector runs`.

## Important Findings
The shared `job_status` enum currently supports `queued`, `running`, `success`, and `failed`, but not `skipped` or `retrying`. To preserve the existing schema contract without a migration in this Task, skipped runs are stored as successful job logs with `metadata.run_status = "skipped"` and retry information is stored in job metadata (`attempts` and `retried`).
