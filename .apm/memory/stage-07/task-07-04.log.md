# Task 7.4 - Backup Restore Drill

## Summary
Validated the documented PostgreSQL backup and restore procedure against the local development Compose stack using safe test data. No documentation or script corrections were needed, so no commit was made on `chore/backup-restore-drill`.

## Details
The local Compose stack was already running from the project root with `reverse-proxy`, `frontend`, `backend`, `scheduler`, `worker`, `postgres`, and `redis`. Health and readiness checks were green before the drill.

Inserted one safe raw-intelligence marker row tied to the existing `sample` source:

- `external_id`: `backup-drill-20260520T1244Z`
- `title`: `Backup restore drill marker`
- `id`: `ed8bd676-bc06-4bd6-ac68-16beda61751d`

Created the documented timestamped backup, verified it with `pg_restore --list`, then created a second pre-restore safety backup as required. Deleted the marker row from the live database before restore to prove the restore was effective. Stopped application writers, kept PostgreSQL and Redis running, dropped/recreated the database, restored from the drill dump, ran migrations, restarted services, and verified the marker row came back. Removed the marker row after the proof so local test data was not left behind.

The stack remains running because it was already running when the drill started and the restore sequence brought it back to service.
