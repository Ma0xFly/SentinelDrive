# Task 6.2 - Compose Deployment Verification

## Summary
Verified the full Docker Compose deployment path with Docker Engine 28.3.2, fixed runtime issues found during validation, and committed the scoped changes as `eae2721` (`fix: stabilize compose deployment runtime`). The stack was stopped after validation with `docker compose down`.

## Details
Validated Compose rendering, public port exposure, dependency order, migrations, admin bootstrap, reverse-proxy health/readiness routing, frontend HTTP serving, worker/scheduler Redis connectivity, PostgreSQL connectivity, task registration, and live source sync behavior.

Runtime verification surfaced four deployment issues, all fixed:

- Backend admin bootstrap emitted a Passlib/bcrypt compatibility traceback with `bcrypt==4.3.0`; pinned backend `bcrypt` to `4.0.1`, which removed the warning.
- Worker persistence was writing string values into PostgreSQL enum columns without bind casts; added PostgreSQL enum types with explicit bind casts and regression coverage.
- Worker and scheduler were isolated on the internal network only, which blocked live source egress; added an `egress` Compose network for outbound connector traffic while keeping PostgreSQL/Redis internal.
- NVD live sync failed after network recovery because the default two-year `lastMod` window exceeded the NVD API documented 120-day date-range limit; reduced the default NVD window to 120 days and updated tests/docs.

## Output
- Modified `README.md` with worker egress verification and internal-service exposure notes.
- Modified `backend/requirements.txt` to pin `bcrypt==4.0.1`.
- Modified `docker-compose.yml` to attach `worker` and `scheduler` to an outbound `egress` network while preserving internal PostgreSQL/Redis access.
- Modified `worker/sentineldrive_worker/persistence/tables.py` to align worker table metadata with PostgreSQL enum columns and render enum bind casts.
- Modified `worker/sentineldrive_worker/connectors/nvd_cisa.py` to use a 120-day default NVD window.
- Added `worker/tests/test_persistence_postgres_types.py` and updated `worker/tests/test_nvd_cisa_connectors.py`.

- Updated `docs/deployment.md`, `docs/qa/compose-checklist.md`, `docs/source-configuration.md`, and `docs/testing.md` to match final deployment behavior.

## Compatibility Concerns
This Task discovered compatibility-sensitive runtime behavior:

- `passlib[bcrypt]==1.7.4` is not compatible with `bcrypt==4.3.0` for clean bootstrap logs; the backend runtime now pins `bcrypt==4.0.1`.
- Worker SQLAlchemy metadata must use PostgreSQL enum types with bind casts for PostgreSQL writes, while preserving SQLite-compatible variants for tests.
- Live Connectors require outbound egress in addition to internal database/cache networking.
- NVD CVE API date-range requests must stay within 120 consecutive days.

## Important Findings
The full runtime smoke test validated more than static Compose rendering and found issues that only appeared with live containers and external source access. The final live sync confirmed NVD and CISA source collection work with the corrected egress network and NVD window, while PostgreSQL/Redis remained internal and no credentials were exposed in logs.
