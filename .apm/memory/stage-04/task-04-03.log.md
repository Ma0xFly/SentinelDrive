# Task 4.3 - Alert Generation and Status APIs

## Summary
Implemented backend alert generation and authenticated alert review APIs on branch `feat/alert-generation-api`. The service creates deterministic alert records for MVP high-risk conditions, avoids duplicate rules per intelligence record, supports list/detail/status workflows, and audits status updates.

## Details
Added reusable alert trigger logic under `backend/app/services/alerts.py`. The service evaluates normalized `ThreatIntelligence` rows using existing score, severity, source, tag, CVE, vendor, component, and `metadata.scoring` signals. It covers critical intelligence, known exploited or CISA KEV signals, high-risk vehicle-critical components, same-CVE multi-source observations, and seven-day high-risk bursts by vendor or component. Targeted evaluation keeps a bounded context window so cross-record rules still work when evaluating one intelligence record.

Added authenticated `/alerts` routes and schemas for evaluation, listing, detail, and status updates. Alert detail responses include a normalized intelligence summary and safe source attribution for analyst review. Status updates preserve before/after status and notes through `record_audit_event`, using `ALERT_CLOSURE` for closed alerts and `STATUS_CHANGE` otherwise.

Extracted shared response safety helpers to `backend/app/api/safety.py` and refactored the existing intelligence route to use them, preserving prior sensitive metadata and URL redaction behavior. Updated documentation to describe the new alert API surface while keeping alerting out of Connectors and external notifications out of scope.
