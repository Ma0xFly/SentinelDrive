# Task 8.1 - 工作台响应式布局修复

## Summary

已修复工作台主内容区宽屏利用不足、来源管理右侧详情容易被挤压的问题，并补充桌面视口布局 E2E 断言。前端构建、E2E 和 diff 检查均已通过。

## Details

本任务在 `fix/workbench-responsive-layout` 分支完成，布局修复提交为 `830ad1f fix: improve workbench responsive layout`。

主要调整：

- 将 `.content-area` 的最大宽度从 `1180px` 放宽到 `1680px`，避免情报列表和详情页长期挤在过窄中间列。
- 将 split 工作台右侧详情列改为 `clamp(340px, 27vw, 460px)`，并在 `1180px` 以下自动堆叠，避免 `/sources` 右侧信息区被遮挡。
- 为表格、详情块、来源行、元数据网格、长标题、长摘要、错误信息等添加 `min-width: 0`、`overflow-wrap: anywhere`、受控横向滚动和响应式列策略。
- 补充 Playwright 桌面布局测试，覆盖 `1366x768`、`1440x900`、`1920x1080` 三个视口，检查 `/`、`/intelligence/[id]` 和 `/sources` 没有整体水平溢出，并确认来源详情面板在视口内。
- 调整 E2E 登录 helper，使其在已登录或未登录两种状态下都稳定工作。

没有更改 API 契约、认证行为、后端接口或业务功能；没有实现 AI ingest、知识图谱、工单、多租户 RBAC 等非本任务功能。
